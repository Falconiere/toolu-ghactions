# `review-run.payload.json` provenance

Generated by `buildPayload()` (`src/report/payload.ts`), driving the real pipeline
from a genuinely recorded model completion — not hand-authored.

**Source completion:** `src/llm/__tests__/fixtures/deepseek-success.json`, the
fixture `deepseek.test.ts` documents as "a genuine api.deepseek.com completion,
recorded via a one-off live call — no hand-faked data." It carries one finding
(`src/math.ts:1`, severity `high`, raw category `"logic"`).

**How it was produced** (see `payload.test.ts`'s `buildFixturePayload()`, which
reproduces these same steps and asserts byte-identical output against this file):

1. `reviewWithModel()` (provider `"deepseek"`) replays the recorded completion
   through a fetch stub — the same parse path `deepseek.test.ts` exercises — to get
   a real `ProviderResult`.
2. `validateFindings()` anchors the one finding against a synthetic diff whose only
   changed line is `src/math.ts:1` (the line the finding cites), then `fingerprint()`
   stamps it, exactly like `pipeline/reviewCall.ts`'s own `validate()`.
3. The stamped finding is run through `partitionFindings()` as a first-round,
   `toCreate`-only reconcile plan (no prior state, nothing resolved/suppressed) —
   it lands in the `new` bucket.
4. `buildPayload()` turns that into the wire body. Its raw `category: "logic"` has
   no `CATEGORY_ALIASES` entry, so `normalizeCategory()` — the only call site in
   the repo — reports it as `"other"`, proving the normalization is actually on
   this path (spec AC-35), not merely unit-tested.

**Hand-authored, by necessity:** the repo/PR/run identity fields (`repo.id`,
`repo.fullName`, `pull.*`, `run.githubRunId`, `run.githubRunAttempt`,
`run.startedAt`, and the injected clock) are environment data no recorded model
completion carries — `buildFixturePayload()` calls `buildPayload()` directly with
hand-picked values, bypassing `GithubContext`/`report-run.ts` (which now resolve
these for a real run — see `payload.ts`'s module doc, "IDENTITY GAP"). These are
realistic placeholder values, not signal the platform's tests should assert on;
the finding content and its normalized category are the real, recorded part this
fixture exists to prove.
